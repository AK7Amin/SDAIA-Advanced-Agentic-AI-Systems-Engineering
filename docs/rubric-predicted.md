## 1. البنود المتوقعة (100 نقطة | النجاح ≥60)

| # | البند | نقاط | المطلوب (بأسلوب rubric الدورة السابقة) |
|---|---|---|---|
| 1 | المعمارية الوكيلية Agentic Architecture | 25 | مخطط حالة LangGraph حقيقي: عقد، **حواف شرطية**، وحلقة واحدة على الأقل (تحقق→إعادة تنفيذ). نمط تخطيط معلن (Plan-and-Execute أو ReAct) يقرر فيه النموذج تدفق التحكم فعلًا — سلسلة خطية مقنّعة لا تُحتسب. |
| 2 | تعدد الوكلاء Multi-Agent | 20 | وكلاء متخصصون بأدوار واضحة + وكيل منسق. رسائل بينية **محددة النوع typed** (Pydantic) لا نصًا حرًا. تقرير المتخصص يصل المنسق مباشرة (لا telephone game). |
| 3 | الذاكرة والحالة Memory & State | 15 | checkpointer دائم حقيقي (SqliteSaver/PostgresSaver) مع **إثبات إيقاف واستئناف عبر عمليتين منفصلتين**. ذاكرة خارجية متجهية (ChromaDB) للسياسات. |
| 4 | الحواجز والأمن Guardrails & Security | 20 | حواجز مدخلات ومخرجات آلية (حقن، PII). **تقرير اختبار اختراق** يوثق هجومًا فعليًا (حقن مباشر + غير مباشر عبر وثيقة) قبل وبعد التحصين. human-in-the-loop للفعل الخطر. |
| 5 | المراقبة والتكلفة Observability & Cost | 15 | تتبع traces لكل تشغيلة، عدادات (توكنز، تكلفة، كمون latency، نجاح/فشل) بـPrometheus-client أو ما يعادله، ولوحة عرض. |
| 6 | النشر والعرض Deployment & Docs | 5 | تشغيل بأمر واحد (Docker أو سكربت)، README كامل، عرض معماري. |

## 2. قواعد التقييم المتوقعة (منقولة نمطيًا من rubric الدورة السابقة)

- **المكتبة الحقيقية لكل بند**: langgraph حقيقي، checkpointer حقيقي، chromadb
  حقيقي — «محاكاة لا تكسب البند مهما حَسُن كودها».
- **شغّل الكود واحتفظ بالمخرجات**: سجلات تشغيل حقيقية هي الدليل، لا وجود الكود.
- **أثبت مسارات الفشل لا السعيدة فقط**: حقن يُحجب فعلًا، سقوط API يُتجاوز
  فعلًا بfallback، عملية تُقتل ويُستأنف من الcheckpoint فعلًا.
- **متطلبات GitHub الست**: وصف واضح، README مهني، توثيق تقني، ممارسات git
  سليمة (تاريخ تدريجي لا رفعة واحدة)، نسبة البرنامج التدريبي، رابط SDAIA Academy.
